# تواصل – مساحة التعلم

منصة دردشة تعليمية عربية (RTL) تربط المعلم بطلابه: محادثة لكل درس، رسائل نصية وصور من المعرض أو الكاميرا مباشرة، تحديث لحظي بين الأجهزة، وحفظ دائم لكل المحادثات في حساب المعلم.

- **الواجهة:** React + Vite + TypeScript + Tailwind CSS، خط Cairo، تطبيق PWA قابل للتثبيت.
- **الخلفية:** Supabase (المصادقة، قاعدة البيانات Postgres، Realtime، Storage) مع سياسات RLS.
- **لا يوجد أي مفتاح سري في كود المتصفح:** الموقع يستخدم المفتاح العام فقط، والحماية الفعلية في قاعدة البيانات.

## المزايا

**لوحة المعلم:** زر «+ إنشاء محادثة جديدة»، قائمة المحادثات مع اسم الدرس وتاريخه وعدد الطلاب وعدد الرسائل غير المقروءة والحالة (مفتوحة/مغلقة/منتهية/مؤرشفة)، بحث، إغلاق وإعادة فتح، أرشفة، وحذف بعد تأكيد.

**إنشاء محادثة:** اسم الدرس، وصف، الصف، مفتوحة لكل من يملك الرابط أو مقيّدة (قائمة أسماء أو رموز دخول فردية)، وقت انتهاء اختياري. بعد الإنشاء: رابط فريد، نسخ، مشاركة، رمز QR (وعرضه بملء الشاشة للسبورة)، وفتح المحادثة.

**دخول الطالب:** شاشة ترحيب باسم الدرس واسم المعلم، حقل «اكتب اسمك قبل الدخول» إلزامي (يُرفض الفارغ والمسافات)، ويبقى الطالب داخل المحادثة عند تحديث الصفحة. لا يمكن الدخول باسم مستخدم مسبقًا في المحادثة نفسها، ويمكن للمعلم فرض قائمة أسماء أو رموز دخول فردية (6 أرقام) لمنع الانتحال.

**الدردشة:** رسائل المعلم بلون مختلف عن رسائل الطلاب، اسم المرسل والوقت، نص، صورة من المعرض، التقاط صورة بالكاميرا، معاينة وإلغاء قبل الإرسال، تكبير الصورة، مؤشر «رسائل جديدة»، رد على رسالة محددة، وتحديث لحظي دون إعادة تحميل.

**أدوات المعلم داخل المحادثة:** قائمة الطلاب ووقت دخولهم وعدد رسائلهم، إيقاف طالب، رد على أي طالب، إعلان لجميع المشاركين، حذف رسالة مخالفة، تثبيت رسالة، «إجابة مميزة»، إغلاق/إعادة فتح، بحث في الرسائل، معرض الصور مع اسم المرسل، تنزيل الصور، البلاغات، وتصدير PDF وExcel.

**الخصوصية:** صور فقط (JPG/PNG/WEBP/GIF) بحد 5 ميجابايت، تُضغط في الجهاز وتُزال منها بيانات الموقع (EXIF)، الطالب يبلغ عن رسالة غير مناسبة، ولا يحذف إلا رسائله.

## ربط Supabase (مرة واحدة)

> إن كنت تستخدم مشروع Supabase الحالي `pqkaotqtwdaoolbjzpyk` فقد طُبّقت هذه الخطوة بالفعل. اتبعها فقط عند إنشاء مشروع جديد.

1. أنشئ مشروعًا من [supabase.com/dashboard](https://supabase.com/dashboard).
2. افتح **SQL Editor** ← **New query**، والصق محتوى الملف [`supabase/schema.sql`](supabase/schema.sql) كاملًا ثم اضغط **Run**.
   ينشئ الملف: الجداول (بادئة `tw_`)، دوال الطلاب الآمنة، سياسات RLS، مخزن الصور الخاص `tw-images`، وقنوات التحديث اللحظي. الملف آمن للتشغيل أكثر من مرة.
3. من **Authentication ← URL Configuration**:
   - **Site URL:** رابط موقعك بعد النشر (مثل `https://tawasul.netlify.app`).
   - **Redirect URLs:** أضف `https://رابط-موقعك/**`.
4. (اختياري) من **Authentication ← Providers ← Email** يمكنك إيقاف «Confirm email» إن أردت أن يدخل المعلم مباشرة بعد إنشاء الحساب دون رسالة تأكيد.
5. من **Project Settings ← API** انسخ:
   - **Project URL**
   - المفتاح العام **anon / publishable** فقط.

   ⚠️ لا تستخدم مفتاح `service_role` في الموقع أبدًا.

## التشغيل على جهازك

يتطلب Node.js 20 أو أحدث.

```bash
npm install
cp .env.example .env      # ثم ضع الرابط والمفتاح العام
npm run dev               # يفتح على http://localhost:5173
```

لاختبار الكاميرا من الجوال على الشبكة المحلية يلزم HTTPS، لذا الأسهل الاختبار بعد النشر.

## النشر على الإنترنت

الموقع ملفات ثابتة (مجلد `dist`) ويعمل على أي استضافة. أسهل خيارين:

### Netlify (موصى به)

1. ادخل [app.netlify.com](https://app.netlify.com) ← **Add new site ← Import an existing project** واختر مستودع GitHub.
2. الإعدادات تُقرأ تلقائيًا من `netlify.toml` (الأمر `npm run build` والمجلد `dist`).
3. من **Site configuration ← Environment variables** أضف:
   - `VITE_SUPABASE_URL` = رابط المشروع
   - `VITE_SUPABASE_ANON_KEY` = المفتاح العام
4. اضغط **Deploy**، ثم ضع رابط الموقع في إعدادات Supabase (الخطوة 3 أعلاه).

### Vercel

نفس الخطوات: **Add New ← Project**، اختر المستودع، أضف المتغيرين نفسيهما، ثم **Deploy**. ملف `vercel.json` يتكفل بتوجيه الروابط.

> بعد أي تغيير في المتغيرات أعد النشر (Redeploy) لأنها تُضمَّن وقت البناء.

## اختبار الدخول من جهاز المعلم وأجهزة الطلاب

1. **جهاز المعلم (كمبيوتر أو آيباد):** افتح الموقع ← «دخول المعلم» ← أنشئ حسابًا (اسمك كما يظهر للطلاب + بريد + كلمة مرور).
2. اضغط **+ إنشاء محادثة جديدة** واكتب «التوكل على الله» ← **إنشاء المحادثة**.
3. اعرض رمز QR بملء الشاشة أو انسخ الرابط وأرسله.
4. **جوال الطالب الأول:** امسح الرمز ← اكتب «أحمد» ← أرسل رسالة نصية.
5. **جوال الطالب الثاني:** افتح الرابط ← اكتب «محمد» ← زر الكاميرا 📷 ← التقط صورة ← معاينة ← إرسال.
6. على جهاز المعلم تظهر الرسالتان والصورة فورًا. اضغط ⋮ بجانب أي رسالة ← «رد على الرسالة».
7. أغلق المتصفح على جهاز المعلم ثم افتح الموقع من جديد: ستجد المحادثة والرسائل والصور محفوظة في اللوحة.
8. على الجوال: من Safari زر المشاركة ← «إضافة إلى الشاشة الرئيسية» لتثبيته كتطبيق، ومن Chrome على أندرويد ← «تثبيت التطبيق».

إن ظهر في رأس المحادثة «تحديث دوري» بدل «مباشر» فالقناة اللحظية محجوبة على تلك الشبكة، وتستمر المحادثة بالتحديث كل 3 ثوانٍ تلقائيًا.

## الأمان والخصوصية

| الطبقة | ما يحدث |
|---|---|
| حساب المعلم | Supabase Auth (بريد + كلمة مرور). كل محادثة مرتبطة بـ `owner_id`، وسياسات RLS تمنع أي معلم من رؤية محادثات غيره. |
| الطلاب | بلا حسابات. لا يملكون أي صلاحية على الجداول مباشرة؛ كل ما يفعلونه يمر عبر دوال `tw_join` و`tw_feed` و`tw_send`… التي تتحقق من «رمز جلسة» عشوائي (32 بايت) يُحفظ مُشفّرًا (SHA-256) في القاعدة. |
| منع الانتحال | لا يتكرر الاسم داخل المحادثة (مع توحيد الهمزات والتشكيل)، وخيار قائمة أسماء، وخيار رموز دخول فردية مع حد للمحاولات الخاطئة. |
| الصور | مخزن خاص غير عام. الرفع مسموح فقط لمشارك فعلي في محادثة مفتوحة وداخل مجلده هو، والقراءة بروابط موقّعة مؤقتة لمن يعرف المفتاح السري للمحادثة. الصيغ المسموحة صور فقط، والحد 5 ميجابايت، ويُتحقق من نوع الملف الحقيقي قبل الرفع. |
| التحديث اللحظي | قناة Realtime باسم سري لكل محادثة تُرسل إشعارًا خفيفًا فقط (بلا محتوى)، ثم يجلب كل جهاز ما يحق له عبر الدوال المحمية. |
| لوحة المعلم | محمية بتسجيل الدخول، والطالب لا يملك جلسة Supabase أصلًا فلا يصل إلى أي بيانات معلم. |
| الحذف | الطالب يحذف رسائله فقط، والمعلم يحذف أي رسالة في محادثاته. |

## البيانات التجريبية

من لوحة المعلم: **إضافة بيانات تجريبية** تنشئ محادثتين معلّمتين بـ«تجريبي» (مع طلاب ورسائل وإجابة مميزة ورسالة مثبتة). وزر **حذف البيانات التجريبية** يحذفها وحدها دون المساس بمحادثاتك الحقيقية.

## الاختبارات

- `tests/db-scenario.sql`: يشغّل سيناريو «التوكل على الله» كاملًا على قاعدة البيانات الحقيقية (معلم، أحمد، محمد، صورة، رد، إغلاق) ويتحقق من كل سياسات الحماية، ثم يتراجع عن كل التغييرات تلقائيًا. شغّله من SQL Editor وستظهر النتيجة في رسالة الخطأ `RESULT {...}`.
- `tests/ui-scenario.mjs`: يشغّل السيناريو نفسه في متصفح Chromium على ثلاثة أجهزة (معلم على كمبيوتر، أحمد على iPhone، محمد على كمبيوتر بكاميرا) ويحفظ لقطات الشاشة في `test-results/`.

```bash
npm run build && npx vite preview --port 4173 &
node tests/ui-scenario.mjs
```
